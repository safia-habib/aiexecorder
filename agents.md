# Coding Agent Context — State AI EO Explorer

This file gives AI coding agents (Claude Code, Copilot, Cursor, etc.) the context
needed to work effectively in this repo without re-reading every file.

---

## What this project is

A full-stack RAG web app. Users click a US state on a choropleth map; the app
shows that state's AI Executive Order and lets users ask follow-up questions.
Answers are generated by Azure OpenAI (gpt-4o), grounded in EO text retrieved
from a Qdrant vector store. Every RAG step is instrumented with OpenInference
semantic conventions for tracing in Arize Phoenix or Dynatrace.

## API contract

### `GET /api/health`
Returns `{"status": "ok"|"degraded", "qdrant": "reachable"|"unreachable", "azure_openai": "reachable"|"unreachable"}`.

### `GET /api/states`
Returns `{"states": [...]}` — always 50 entries. If Qdrant is unreachable or the collection
doesn't exist yet, all states return `has_eo: false` (no 500).

### `GET /api/states/{state_code}/eo`
Returns full EO payload or `{"has_eo": false, "message": "..."}`. Qdrant errors return a
graceful message, not a 500.

### `POST /api/ask`
Body: `{"state_code": "CA", "question": "..."}`.
Returns `text/event-stream`:
```
event: token
data: {"token": "Dyna"}

event: token
data: {"token": "trace"}

event: done
data: {"full_answer": "Dynatrace helps..."}
```
If no EO data is found, emits only a `done` event with an explanatory message (no LLM call).

## RAG pipeline

```
POST /api/ask
  └── rag_chain span (CHAIN)
        ├── retrieve(state_code, question)
        │     └── retrieve span (RETRIEVER)
        │           └── embed(question)
        │                 └── embed span (EMBEDDING) → AzureOpenAI embeddings.create()
        │           → Qdrant search filtered by state_code, top_k=3
        └── generate_stream(context, question)
              └── llm_generate span (LLM) → AzureOpenAI chat.completions.create(stream=True)
```

All spans use **OpenInference semantic conventions** from `rag/tracing.py`. Tracing is a
complete no-op when `OTLP_ENDPOINT` is unset.

## Ingestion

Run after deploy (or after updating the spreadsheet):

```bash
# On K8s
kubectl delete job run-ingestion -n ai-eo-explorer 2>/dev/null
kubectl apply -f k8s/jobs/ingest.yaml

# Locally (Docker Compose)
docker exec -it ai-eo-backend \
  python -m ingestion.ingest \
    --data-path /data/State_AI_Executive_Orders_Dynatrace_Report.xlsx \
    --recreate
```

`--recreate` drops and recreates the Qdrant collection (required when embedding model changes).

## Frontend behaviour notes

- `StateMap.jsx` maps TopoJSON geography `NAME` properties to 2-letter state codes via a
  hardcoded `NAME_TO_CODE` dict. Add new states there if needed.
- `AskBox` receives `key={stateCode}` in `StatePanel` to force a full remount on state change —
  this resets the SSE stream and answer text without needing explicit cleanup logic.
- `useAsk.js` uses a `useRef`-stored `AbortController` to cancel in-flight SSE requests when
  the user submits a new question before the previous one finishes.
- `nginx.conf` sets `proxy_buffering off` on the `/api` location — **do not remove this**;
  it is required for SSE tokens to reach the browser through the reverse proxy.

## Common pitfalls

| Symptom | Cause | Fix |
|---|---|---|
| `/api/states` returns all `has_eo: false` | Ingestion not run yet | Run the ingest job |
| Ingestion fails with `missing expected columns` | Spreadsheet column renamed | Update `EXPECTED_COLUMNS` in `ingestion/ingest.py` and matching references in `chunker.py` and `tests/test_ingestion.py` |
| `/api/ask` streams nothing | Azure OpenAI key/endpoint wrong | Check `/api/health` → `azure_openai: unreachable` |
| SSE cuts off mid-stream | nginx buffering enabled | Ensure `proxy_buffering off` in nginx.conf and Ingress annotation |
| Backend pod stuck in `Init:0/1` | Qdrant not ready | Check `kubectl logs -n ai-eo-explorer <pod> -c wait-for-deps` |
| `openinference` ImportError on startup | Package not in image | Rebuild image; `tracing.py` has a graceful fallback so app still starts |
